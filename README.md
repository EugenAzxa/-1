# Миллениум - сайт-презентация

Статический сайт компании, которая делает две вещи:

1. **Фотозоны для музеев, парков и выставок.** Конструкция, свет, экран выбора сюжета,
   AI-пресеты под тему экспозиции, печать и выдача по QR.
2. **Выездные съёмки в детских садах и школах.** Студийный свет, гардероб, стилист,
   ретушь, выпускные и новогодние альбомы.

Плюс внутренняя страница `presets.html` - библиотека промптов для фотографов и ретушёров.

## Страницы

| Файл | Что внутри |
| --- | --- |
| `index.html` | Главная: оба направления, пять шагов, образы, кейс, модель работы, частые вопросы |
| `museums.html` | Музеям и паркам: состав фотозоны, темы, конфигурации, сроки, требования к площадке |
| `schools.html` | Сады и школы: съёмочный день, что привозим, сюжеты, альбомы, организация |
| `worlds.html` | Витрина AI-образов и требования к исходным кадрам |
| `presets.html` | Рабочая страница команды: промпты, параметры генерации, чек-лист отбора |
| `contacts.html` | Контакты, форма заявки, формальная сторона работы |

## Сборка

Правим исходники в `src/`, собираем командой:

```bash
python3 build.py
```

Скрипт склеивает страницы из `src/pages/*.html` с общей шапкой и подвалом, подставляет
контакты и заново собирает библиотеку пресетов. Готовые `.html` лежат в корне - их и
публикуем. Зависимостей нет, нужен только Python 3.

Локальный просмотр:

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

## Что где править

| Задача | Файл |
| --- | --- |
| Название компании, телефон, почта, Telegram, город | `CONFIG` в `build.py` |
| Пункты меню | `NAV` в `build.py` |
| Шапка, подвал, мета-теги | `LAYOUT` в `build.py` |
| Блок звонка | `src/partials/cta.html` |
| Текст страницы | соответствующий файл в `src/pages/` |
| Промпты, параметры генерации, чек-лист | `src/presets.py` (оттуда же собирается `PROMPTS.md`) |
| Цвета, типографика, компоненты | `assets/css/style.css` |
| Палитры светлой и тёмной темы | блоки `:root` и `:root[data-theme="dark"]` там же |

После любой правки в `src/` обязательно `python3 build.py`.

## Темы

Сайт открывается в светлой теме, в шапке есть переключатель на тёмную.
Выбор гостя хранится в `localStorage` (ключ `aib-theme`) и применяется до
отрисовки страницы маленьким скриптом в `<head>` - иначе тёмная тема моргала
бы белым при каждом переходе.

Все цвета берутся из переменных в начале `style.css`: светлая палитра лежит
в `:root`, тёмная - в `:root[data-theme="dark"]`. Зашитых цветов в правилах
нет, кроме элементов, которые всегда лежат поверх фотографии (подписи на
кадрах, карточки направлений) - они остаются светлыми в обеих темах
намеренно.

Для акцентов есть по две переменные: `--gold` и `--blue` для заливок кнопок,
`--gold-ink` и `--blue-ink` для текста. На светлом фоне яркое золото даёт
контраст около 2:1, поэтому текстом идёт затемнённый вариант. Контраст
проверен на всех шести страницах в обеих темах.

## Фотографии

В `assets/img/kiosk/` лежат кадры фотозоны в атриуме: `main.jpg`, `kids.jpg`,
`mother.jpg` стоят в сетке первого экрана, `atrium.jpg` - на странице музеев,
`overhead.jpg` и `talking.jpg` пока в запасе. В `assets/img/` - четыре кадра
космической темы из концепт-презентации.
Реальные работы добавляются в `assets/img/works/` под фиксированными именами -
см. `assets/img/works/README.md`. Пока файла нет, карточка показывает фирменную
заливку с иконкой, поэтому сайт не выглядит недоделанным.

## Экран загрузки

На экране видоискатель с меняющимися локациями (кадры лежат в
`assets/img/intro/`), камера с золотым объективом, полоса реального
прогресса и надпись «Выбери свой мир» с названиями миров.

Финал - щелчок затвора: шторки видоискателя схлопываются, экран уходит в
черноту, бьёт белая вспышка, и из-под неё расходятся шторки. Через черноту
вспышка читается в обеих темах: без неё белое по белому в светлой теме
просто терялось.

Как он себя ведёт:

- полоса заполняется по реальной загрузке кадров первого экрана: всё, что
  ниже, грузится лениво и никогда не дождалось бы события загрузки;
- полоса никогда не замирает и не показывает 100% раньше времени;
- показывается минимум 0.75 секунды и снимается не позже 3.2 секунды от
  старта навигации, даже если сеть лежит;
- внутри одной сессии показывается один раз: переход на соседнюю страницу
  снимает его мгновенно (флаг в `sessionStorage`, ключ `aib-intro`);
- при `prefers-reduced-motion` и без JS не показывается вообще;
- **`?intro` в адресе показывает вступление принудительно** -
  `photo-bureau.vercel.app/?intro`, удобно показывать клиенту.

Тайминги правятся в `assets/js/main.js`: `MIN_MS` и `MAX_MS`.

## Кеш картинок

Картинки кешируются на сутки, поэтому `build.py` подставляет к каждой метку
версии: `assets/img/x.jpg?v=<хэш файла>`. Заменили файл с тем же именем -
метка изменилась, браузер забрал новый. Без этого замена кадра сутки не
доезжала бы до тех, кто уже был на сайте.

## Связь с клиентом

Формы на сайте нет намеренно: везде одна кнопка со ссылкой `tel:`, звонок идёт
Андрею. Номер и имя лежат в `CONFIG` (`phone`, `phone_href`, `manager`), блок
звонка - в `src/partials/cta.html`, он подключается на каждой странице.

## Публикация

Сайт живёт на Vercel: **https://photo-bureau.vercel.app**
(проект `photo-bureau` в аккаунте eugenazxa).

Выкатка новой версии:

```bash
python3 build.py
npx vercel deploy --prod
```

Настройки лежат в `vercel.json`: адреса без `.html` (`/museums` вместо
`/museums.html`, старый адрес отдаёт постоянный редирект), картинки кешируются
на сутки, стили и скрипты проверяются при каждом заходе, чтобы правки
доезжали сразу. Исходники (`src/`, `build.py`, `README.md`, `PROMPTS.md`)
на сервер не попадают - их отсекает `.vercelignore`.

Свой домен подключается так: `npx vercel domains add <домен>` и затем
`npx vercel alias` либо через панель проекта, раздел Domains.

Альтернатива - GitHub Pages: Settings - Pages - Deploy from branch, ветка
`main`, папка `/root`. Файл `.nojekyll` для этого уже лежит в репозитории.

## Правовая сторона

- Не воспроизводим защищённых персонажей, логотипы и символику франшиз - только
  собственные архетипы. Это прописано и в тексте сайта, и в промптах.
- Детские фотографии публикуем только при наличии письменного согласия родителей.
- Шаблоны согласия и регламент хранения кадров упоминаются на сайте, сами документы
  ведём отдельно.
